# Nine Ways to Check If an AI System Is Correct

This week has 9 papers. Each paper checks, verifies, or measures the uncertainty of an AI system in a real way. The first paper builds a formal protocol. This protocol checks if a predictor's probability answers agree with each other. TCS-BENCH builds an automatic proof checker. This checker matches human expert judgment on proof correctness. A new symbolic regression method named ERRLESS gives a confidence level for each formula, not one fixed answer. A network verifier updates its own rules with a coding agent and a real-router oracle. Decoding-Level Taboo forces a language model off its normal word path to find hidden weak points. UniProbe reads internal signals inside a vision-language model and flags false statements token by token. CRUISE gives each sensor of a self-driving car an uncertainty score. Dynamic Distribution-Aware Uncertainty Tracking follows uncertainty in a vision-language model as the input data shifts. An audit method named J-Access checks if a language model still holds "unlearned" information, and warns against using the audit itself as a training target.

**[How to Verify Consistency of Probabilistic Claims](http://arxiv.org/abs/2608.11181v1)** — An AI model can output a probability for many different, related questions. Under the basic rules of probability, these separate answers should agree with each other. In practice, a model can contradict itself across two questions without anyone noticing, because nobody checks. This paper builds a new check for that exact failure. In the check, a tester asks the AI model a small number of targeted questions. Along with its answers, the AI model produces a compact witness. This witness is a small package of extra numbers. The witness lets the tester confirm the answers are consistent. The tester does not need to recompute the model's full internal reasoning. The verification contribution is this: a method that catches inconsistency from a handful of questions and a small witness, not a full audit of the model. The paper proves the check sits in NP. NP is the class of problems whose answers are hard to find but quick to check once you have the right proof. This means an efficient check exists even as the number of questions grows large. The result opens a concrete path toward AI models that carry their own proof of consistency alongside their answers. A user would not need to trust the numbers at face value.

**[TCS-BENCH](http://arxiv.org/abs/2608.09538v1)** — TCS-BENCH tests language models on real research-level proofs from top theory conferences: STOC, FOCS, and SODA. The verification contribution is not the benchmark itself. The verification contribution is how the benchmark grades a proof. The paper rejects simple text matching as a grading method. The paper also rejects an ungrounded LLM judge. Instead, the benchmark uses a dedicated verification agent. This agent checks whether a generated proof is logically correct, step by step. The paper tests this verification agent against human expert graders on a held-out set. The agent matches expert judgment on more than 90 percent of cases. This gives the field a validated, automatic way to check AI-written proofs at scale.

**[Bayesian Symbolic Regression with Entropic Reinforcement Learning](http://arxiv.org/abs/2608.09617v2)** — Symbolic regression finds a formula that fits a set of data. A normal method returns one best formula. This single answer hides the real uncertainty. A new policy named ERRLESS fixes this problem. ERRLESS builds a formula as a tree. ERRLESS trains with a maximum-entropy reinforcement learning method. This training makes the sampling distribution of ERRLESS approximate the true Bayesian posterior over formulas. The system does not collapse onto one guess. The specific uncertainty-quantification contribution is this: ERRLESS returns a spread of plausible formulas, plus a confidence level for each one, calibrated against noisy, sparse data. On the Feynman benchmark, ERRLESS also beats baseline methods at capturing this uncertainty correctly.

**[Self-evolving network verifiers](http://arxiv.org/abs/2608.11340v1)** — A network verifier checks the rules of a computer network against a formal model. A standard verifier only knows the network behavior an engineer typed in by hand. New protocol versions break this static knowledge. This paper removes the manual step. A coding agent proposes new rules for the verifier's formal model. A router oracle, built from real router behavior, supplies ground truth for these rules. A counterexample-guided loop compares the agent's rules against the oracle output. The loop refines the rules until the rules match reality. The verification contribution is a self-updating formal model, not a one-time proof. On a roughly 3,000-line SMT-based verifier, the system learns three new network features by itself: OSPF areas, BGP route reflection, and L3VPN over EVPN. The system even learns vendor-specific quirks for these features.

**[Decoding-Level Taboo](http://arxiv.org/abs/2608.09900v2)** — A standard evaluation tests a language model only under normal generation conditions. This kind of test can hide real weak points. This paper builds a stress test named Decoding-Level Taboo. The test blocks the model's preferred word choices at the decoding step. This block forces the model onto an unfamiliar word path. The validation contribution is this forced-path condition itself: a repeatable way to check robustness that a normal benchmark cannot reach. The result shows a clear pattern. A larger model, or a model with better alignment, degrades less under this forced condition. The paper recommends the method for pre-deployment checks. The paper also recommends the method for safety-guardrail testing.

**[UniProbe](http://arxiv.org/abs/2608.10835v1)** — A vision-language model can generate a fluent but false statement about an image. This paper builds a tool named UniProbe to catch this at the token level. UniProbe reads the internal computation trace from a single forward pass of the base model. UniProbe routes this trace through three structure-specific modules: a graph network for object relations, a vision transformer for spatial layout, and a sequence network for token order. The verification contribution is this internal-signal classifier. The classifier flags whether each output token is grounded or false, without a second, external judge model. A streaming mode flags a false token in real time as the model generates it. Across multiple models, UniProbe reaches the best known detection accuracy. UniProbe cuts the hallucination rate by up to 55 percent.

**[CRUISE](http://arxiv.org/abs/2608.09202v1)** — A self-driving car reads data from a camera, a lidar sensor, and a radar sensor. Sensor reliability changes with weather and light. This paper builds CRUISE around a single uncertainty-quantification idea. A vision-language model gives a pixel-level uncertainty score for each sensor at each point in the scene. A dynamic fusion module reads this score. The module leans on the more reliable sensor during bad conditions, for example poor visibility. The framework also models the connection between the different sensor types, instead of treating each sensor as independent. The result is a perception system that adjusts to real, measured sensor trust levels, not a fixed trust assumption.

**[Dynamic Distribution-Aware Uncertainty Tracking](http://arxiv.org/abs/2608.09011v1)** — Most post-hoc uncertainty methods for AI models assume a fixed test data distribution. These methods degrade once deployment data drifts away from training conditions. This paper builds DDA-UQ to track this drift directly. DDA-UQ fits a Gaussian mixture model over the embedding space during training. This model captures the structure of the training representations. At test time, DDA-UQ uses this structure to produce a live, adjusting uncertainty estimate, instead of one static calibration. The system recalibrates its confidence as the input distribution shifts. This dynamic recalibration is the specific uncertainty-quantification contribution. DDA-UQ beats current state-of-the-art UQ baselines for vision-language models.

**[Measure, Don't Optimize: Forecasting Recovery in LLM Unlearning](http://arxiv.org/abs/2608.11408v1)** — A company can remove a fact from a language model. This process has the name "unlearning." Prior work shows the removed fact often still exists inside the model in a hidden form. This paper builds an audit tool named J-Access for this exact problem. J-Access measures how reachable a supposedly-removed fact still is through the model's internal pathways, separate from what the model states out loud. The paper tests whether this measurement predicts how fast a light fine-tuning step can recover the fact. The measurement predicts recovery speed at the model level. The validation-methodology contribution is a warning result. When a team optimizes a model directly against this audit score, the model does not delete the fact. The model only hides the fact better. The paper's advice is clear. Keep the audit as an independent diagnostic. Do not turn the audit into a training target.
